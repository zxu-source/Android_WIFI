# 开发与联调工作流

1. 按 [实施计划](../../docs/plans/implementation-plan.md) 选择当前阶段，说明前置条件和完成标准。
2. 读取对应需求、设计和协议，检查现有代码和用户修改。设计改变先更新文档；仅整理文档的任务不开展功能开发。
3. 实现小范围可验证的任务；共享协议变化同时更新样例、模拟端和测试，未实现的板端变更明确记入后续任务。
4. 按变更风险验证，不把未运行的检查写成通过；环境问题与源码问题分开记录。
5. 网络失败先区分权限、WiFi 路由、地址、服务、协议、驱动；写请求超时先读状态，禁止自动重复非幂等动作。
6. 按 [验收清单](../../docs/testing/acceptance.md) 收集模拟、HTTP、真机、实物的各层证据。
7. 交付说明完成项、实际验证、未完成项和下一阶段；Git 发布按用户任务和实际历史处理。

当前完成的是规划文档。后续实施从 P0 开始；未提供的第 4 项不据此扩展任务。
