# 静默轮询与稳定布局

日期：2026-10-16。用户反馈自动刷新时页面闪烁、上下抽动。本轮修复显示与请求调度，不改变通信字段、轮询间隔或下位机能力模型，也不恢复手动刷新清单按钮。

## 原因和方案

原实现每两秒读取状态时都设置 refreshing=true；UI 据此插入/移除进度条并禁用整页控件。插入进度条会改变连接卡片高度，禁用/恢复控件造成周期性颜色变化。

只给进度条补占位仍会让整页控件闪烁；只隐藏动画却继续丢弃读操作期间的点击也不可取。采用静默轮询与主动读取分离：前台轮询和回前台读取不设置可见刷新状态，仅更新确认值和时间；主动“读取状态”保留固定高度进度槽。外设等待确认提示同样预留一行，静态列表区段使用稳定 key。

## 交互与一致性

- 静默读取不禁用控件；主动读取和实际控制期间保留明确的忙碌反馈。
- 用户在静默读操作期间提交目标时，立即显示待确认目标；仅允许一个待处理控制，等当前读取释放串行锁后再发送一次，不自动重试。
- 排队后重新检查会话、前台状态、连接、bootId、清单版本、属性能力与确认值质量；变化时取消或报告错误，不向旧设备/旧能力发送命令。
- 已确认值仍只由合法读取或控制回报更新。断开、切模式、进入后台等状态变化不得触发迟到控制。
- 真正新增/删除外设、错误提示出现等业务变化允许改变布局；不承诺所有页面高度永远不变。

## 验证计划

使用可暂停的模拟 Repository 验证轮询期间的状态、排队控制、重复点击、断开/后台/重启/清单变化及失败保护。模拟器检查主动读取前后卡片边界、等待确认前后外设卡片边界、时间更新时控件与输入保持稳定，并回归既有动态清单、权限/网络与控制流程。构建新版 APK，记录实际执行结果和实物未测限制。
