# 设备功能清单与动态控制面板

日期：2026-10-16。依据用户提供的讨论截图完善已有 v1 实现，不更换传输协议。

## 本次设计

1. 连接成功前，安卓主动 GET `/api/v1/device` 拉取功能清单，再 GET `/api/v1/state` 获取确认状态；两者合法且匹配后才开放控制。
2. `resources` 是外设清单。每项有稳定 id、自定义 name、标准 kind 和 properties；名称只用于显示，id 用于寻址。
3. 标准 kind 保持 `binary-output`（二态开关）、`range-output`（范围/滑条调节）、`sensor`（只读传感）。灯、继电器、风扇和电机均按能力归类，不按物理设备名称编写专属按钮。
4. 具体控件仍由属性的 `type + readable + writable + min/max/step` 决定，kind 用于分类展示，保留原有自定义 kind 的兼容性。未知属性类型不可控制。
5. 增加可选 `capabilitiesRevision`，同时出现在清单和状态中。旧设备两处都省略时继续兼容；新设备修改名称、资源或属性约束时递增该字段，安卓在正常状态轮询中发现变化后自动重拉清单。
6. 不保留独立的手动刷新清单按钮或回调；旧固件或用户需要主动重载时复用断开重连（“重新连接”亦可），每次连接自动获取清单。自动更新失败保留最后一次确认的面板，但停用写操作并提示错误。
7. 模拟模式展示两盏不同名称的灯和风扇，并支持模拟新增外设，以验证不修改安卓代码也能生成新控件。

## 方案取舍

推荐并采用客户端主动获取：复用已有 HTTP，明确请求失败和重试边界。设备主动推送需要另增 WebSocket、SSE 或 TCP 长连接，不作为本轮依赖。固定写死外设面板无法满足截图的扩展目标，因此继续使用能力驱动的面板。

“无级调节”指交互上的滑条，实际精度由外设声明的 step 决定；不把电机控制范围或 GPIO、电平假定在安卓端。设备只能报告实际注册的资源。
