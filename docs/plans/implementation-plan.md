# 项目实施计划：安卓优先，随后接入 ESP8266

日期：2026-10-09。状态：待实施。设计依据：[系统设计](../design/system-design.md)、[协议 v1](../protocol/wifi-control-v1.md)、[实验要求](../requirements/lab12-android-wifi.md)。本轮只整理文档和代理目录，不修改业务代码。

## 1. 当前基线与已知条件

- 当前 Activity 仅显示 Hello Android，无网络、设备、外设控制或模拟模式。
- Kotlin/Compose/Material3，applicationId `edu.wifi.light`，minSdk 23，compileSdk/targetSdk 37。
- Wrapper 9.6.0、AGP 9.4.1、Kotlin 2.2.10、Compose BOM 2026.02.01，daemon toolchain 25。保持现有配置，先构建核验，不凭版本号盲目升级/降级。
- 本机已发现 Android SDK 平台目录 android-23、android-34、android-37.0；平台目录存在不等于完整构建环境可用，真机连接也未核实。
- 公共仓库此前通过 API 上传，远端有 Seed repository + Initial commit，而本地有独立 root commit。开始提交/推送前先 fetch 和比较历史/文件；当前计划不执行合并或强制推送。
- 手机/板型/外设尚未提供；安卓模拟开发可先做，最终真机验收必须补充这些信息。

## 2. 总体顺序与完成定义

```text
P0 工程基线
 → P1 协议和领域模型
 → P2 模拟模式
 → P3 安卓操作界面
 → P4 真正 HTTP 与 Android 网络适配
 → P5 安卓客户端验收
 → P6 ESP8266 固件
 → P7 手机 + 开发板 + 外设联调
 → P8 扩展验证与实验材料
```

“安卓完成”是 P0–P5 达标：可安装、有真实 HTTP 客户端、能在模拟模式和协议一致的局域网模拟服务中完成操作/错误恢复，且真机安装及网络可测。它不等同于完成整个实验。最终实验完成还要求 P6–P8 的真实 WiFi 外设控制证据。

## 3. P0：确认工程可构建

任务：

1. 检查仓库根目录和已有修改，读取 AGENTS 与本计划。
2. 核对 Android Studio 的 JDK、daemon toolchain 25 可用性、SDK 37、Wrapper 校验和、依赖解析。
3. 运行 `gradlew.bat --version`、`gradlew.bat :app:assembleDebug`、`:app:testDebugUnitTest`、`:app:lintDebug`，记录真实结果。
4. 构建不通时区分环境/网络/依赖/源码原因。只修直接阻塞项，保留已有 Android 模板与标识。

产出：可构建基线和 `docs/testing/build-baseline.md`（实施时新增）。验收：APK 生成、基础测试和 lint 结果明确；不能以“目录存在”宣称成功。

## 4. P1：冻结可执行的协议与模型

任务：

1. 建立 core/model、core/protocol、domain 包及 `DeviceRepository` 接口。
2. 模型覆盖设备描述、资源/属性、四种类型、数值约束、质量、bootId/revision、连接状态和结构化错误。
3. 编写 Kotlin serialization DTO 映射，未知字段兼容，未知类型安全降级，版本不兼容阻止写。
4. 创建共享 `protocol/fixtures/`，逐项对应协议样例，明确哪些是模拟外设。
5. 实现数值/地址/端口/ID 校验，错误分为权限、连接、超时、HTTP、解析、版本、驱动。

产出：模型、接口、样例和契约测试。验收：成功/错误 JSON 可解析；非法 boolean、小数 integer、越界值被拒绝；未知字段不会破坏解析；不可用值不是 false/0。

## 5. P2：先完成可替换的模拟设备

任务：

1. `MockDeviceRepository` 实现与真实端一致的接口和状态规则。
2. 提供 LED 开关、PWM 0–100%、只读温度三个资源；可重复配置资源数量与显示名称。
3. 注入可控延迟、断线、超时但已执行、只读错误、未知属性类型、设备重启和迟到响应。
4. 支持确定性测试，不依赖随机故障或现实中的不稳定网络。

产出：安卓内模拟实现。验收：无板端时可操作全部 UI；延迟不会被显示为成功；超时后的 GET 能恢复真实逻辑状态；模拟模式始终可辨识。

## 6. P3：实现安卓操作界面和状态管理

任务：

1. 替换 Greeting 为连接区、设备信息、动态外设卡片、诊断入口。
2. 连接表单校验 IP/主机与端口，保存非敏感设置；默认显示示例地址而非保证地址。
3. ViewModel 管理 StateFlow，UI 不直接发请求；资源写入串行，区分确认值与待确认目标。
4. boolean 控件、数值 slider/输入控件、只读读数/文本控件按描述映射。
5. 数值滑块拖动只更新本地预览，释放后发送一次；步长吸附；对该资源重复写入加互斥，防止无限请求。
6. 处理长名称、多个外设滚动、空资源、旋转、后台恢复、字体放大和暗色主题。
7. 日志采用 100 条上限；错误提供清晰的下一步提示和手动重试。

产出：可独立演示的模拟版安卓界面。验收：界面动作可观察且不阻塞；旋转不重复执行；增加同类型模拟资源不用增加硬编码按钮；未知类型不崩溃。

## 7. P4：真实 HTTP 与真机网络适配

任务：

1. 实现 HTTP Repository，固定超时和 JSON/响应大小上限，关闭缓存与跨主机重定向。
2. 显式设置目标状态，不使用 toggle；bootId/revision/session 检查贯穿请求完成处理。
3. 实现连接、前台 2 秒轮询、断开、取消、后台暂停、恢复读取；一个会话只有一个轮询在途。
4. 声明必要权限，target 37 + OS 37 路径处理局域网运行时权限；拒绝、撤回有可恢复界面。
5. 配置实验 HTTP 明文策略，覆盖 API 23 与 API 24+；验证实际网络库行为。
6. 观察 WiFi 网络并按 Network 绑定 socket/客户端；保留蜂窝数据开启时的测试，不把无互联网热点当失败。
7. 提供 PC 端协议一致的轻量 HTTP 模拟服务（实施阶段新增 `tools/mock-device/`），使用共享 fixtures，可配置 IP/端口、超时与错误，默认绑定 loopback，真机验证时显式绑定局域网网卡。

产出：真实网络实现、PC 模拟服务和联网测试。验收：手机能通过 HTTP 操作 PC 模拟设备；连接不存在地址、错误端口、坏 JSON、权限拒绝均不崩溃；超时不自动重发控制。

## 8. P5：安卓阶段交付

任务：

1. 运行单元测试、MockWebServer 契约测试、关键 Compose UI 测试、lint 和 debug 构建。
2. 在用户手机安装，记录型号、系统版本、权限分支和网络条件；尚无设备时明确标记真机验收未完成。
3. 输出 APK 的实际路径、安装操作、模拟/真实模式使用说明以及已知限制。
4. 核对 P1–P4 不因切换 Repository 出现业务差异。

验收：全部客户端检查完成；Android 可独立使用模拟设备开发演示；真实 HTTP 经过协议服务验证。该阶段还不宣称已经控制 ESP8266 外设。

## 9. P6：ESP8266 固件

前置：板型、外设、引脚和有效电平确认；协议 v1 与安卓端已可测试。

任务：

1. 创建 `firmware/esp8266/`，固定可用 ESP8266 Core/构建工具版本，板级配置与通用 API 分离。
2. 默认 SoftAP；SSID/密码通过本地配置或构建环境输入，提供无真实密钥的样例；串口输出服务 IP、端口和启动状态。
3. LED BinaryOutput 驱动初始化安全关闭；GPIO 有效电平由配置映射，API true 永远表示逻辑开启。
4. 外设注册表生成 device 描述；实现三类端点、body/类型/范围校验、状态快照、revision 和 bootId。
5. 驱动执行结果与 API 错误对应；限制资源和请求容量，记录串口错误与堆内存数据。
6. WiFi 和 HTTP 主循环保持可服务；可读传感器状态独立采样缓存，避免长阻塞操作。
7. 保留 STA 配置入口，但是否实现由首版联调结果决定；不把第二拓扑阻塞首版。

验收：固件构建烧录成功；启动 LED 关闭；合法命令驱动 LED，非法请求无副作用；重启 bootId 改变；描述与注册驱动一致。

## 10. P7：实物联调

任务：

1. 手机连接 ESP 热点并确认本地网络可用；App 按串口显示地址连接。
2. 执行读取初始状态 → 开 → 关 → 重新读取；同步拍摄 LED 变化、App 确认状态和串口记录。
3. 重复控制、拔电重启、离开热点、重新连接、前后台切换、权限撤回等故障测试。
4. 验证手机开启蜂窝网络时也能访问 ESP 热点；针对实际手机路由问题记录处理结果。
5. 覆盖“已执行但响应丢失”：App 显示未知，重新读取恢复；不自动反向操作。

验收：至少 20 次开/关操作，统计成功数、失败类别及恢复结果；这仅证明实验条件下表现，不宣称生产级可靠性。每次成功都有设备回报和实物变化证据。

## 11. P8：扩展验证与实验交付

任务：

1. 实物条件允许时增加第二个 BinaryOutput（低压 LED 或继电器模块），只增加固件资源注册/引脚配置；App 不增加特定资源按钮。
2. 无第二外设时先用模拟能力新增证明安卓扩展，明确实物扩展尚未验证。
3. 若增加 PWM/传感器，实现对应驱动、约束和状态质量，复用现有 UI。
4. 撰写硬件接线表、AP/STA 原理、C/S 请求流程、故障处理和扩展方法。
5. 收集 APK、固件、构建日志、界面截图、实际操作记录，形成 `docs/testing/experiment-results.md`（实施时新增）。

验收：实验五章要求逐项对应证据；上下位机扩展流程可复现；所有“未验证”明确列出，不以模拟状态替代实物结果。

## 12. 风险与决策记录

| 风险/缺失 | 处理 | 最晚解决阶段 |
| --- | --- | --- |
| 手机 OS/型号未知 | 先按运行时版本分支设计，真机记录结果 | P5 |
| SDK/JDK/依赖未验证 | P0 实际构建再决定必要修复 | P0 |
| 板型/GPIO/有效电平未知 | 查询对应板卡资料后建立板级配置 | P6 |
| SoftAP 无互联网导致路由改变 | WiFi Network 绑定 + 蜂窝开启验证 | P4/P7 |
| API37 局域网权限 | 请求/拒绝/撤回路径与实测 | P4/P5 |
| MCU 内存容量 | body/资源上限、有界缓存、固件堆实测 | P6 |
| 输出状态不等于触点反馈 | 明确标记逻辑状态，需要时增加反馈资源 | P7/P8 |
| 本地/远端 Git 历史不同 | 写入仓库前比较，后续同步采用可回退操作 | 下一次 Git 同步 |

用户原请求的第 4 项为空，不推断为任何额外开发或发布任务。此次文档整理完成后，实际功能开发按 P0–P5 开始；手机和板卡信息可随实施补齐。
