# 验收与真机联调清单

当前所有实现验收项均未执行；本文件定义未来检查，不报告成功结果。

## 1. 测试层次

| 层次 | 主要证据 | 不能替代的证据 |
| --- | --- | --- |
| JVM 单元测试 | DTO/校验/状态规则 | Android 系统网络和权限 |
| MockWebServer 契约测试 | HTTP 路径、body、错误、超时 | 手机真实路由与板端驱动 |
| 安卓内模拟模式 | 界面、资源扩展与故障体验 | 真实无线通信 |
| 手机 + PC 模拟 HTTP 服务 | 安装、局域网网络与真实 HTTP | ESP8266 引脚及外设 |
| 手机 + ESP8266 + 外设 | 实验闭环与板端服务 | 长期稳定性或负载安全认证 |

## 2. 安卓完成检查

- [ ] Wrapper debug 构建成功，单元测试与 lint 结果记录。
- [ ] device/state/write 契约及错误 JSON 测试通过。
- [ ] 地址、端口、类型、范围、步长校验覆盖。
- [ ] boolean/range/sensor 按描述渲染，无固定 LED ID 依赖。
- [ ] 只读、未知类型、无有效值、空资源、描述缺失均正确显示。
- [ ] 多次点击、旋转、切后台、切模式、切设备无重复命令和旧响应覆盖。
- [ ] 写超时显示结果未知，通过 GET 确认，不盲目重发。
- [ ] device reboot/bootId 变化使旧请求失效并重新加载。
- [ ] 模拟模式始终显示标识，断开后控件不可发送。
- [ ] 手机真机安装和 PC HTTP 模拟控制成功，记录 OS/型号。
- [ ] OS 37 + target 37 权限授予/拒绝/撤回验证；无此 OS 设备则标记未实测。
- [ ] 可获得的旧系统设备/模拟器覆盖 API 23 或最低版本的网络策略。
- [ ] 大字体、滚动、暗色主题和控件描述可用。

## 3. ESP8266 与实物检查

- [ ] 记录板型、芯片/板卡引脚标记、GPIO、有效电平和供电。
- [ ] 上电默认关闭，SSID 与地址以固件记录为准。
- [ ] App 显示资源来自实际驱动注册，而非模拟配置。
- [ ] 手机开/关动作导致实物变化，并得到匹配 requestId 的成功响应。
- [ ] 至少 20 次开/关记录成功数、延迟和失败分类。
- [ ] 重复设置相同值不反向翻转；无效 JSON/值/只读写无副作用。
- [ ] 掉线不自动发送保存动作；重连先读状态；设备重启重新同步。
- [ ] 无互联网热点 + 蜂窝数据开启条件下仍能控制。
- [ ] GPIO 驱动失败明确报告，不显示控制成功。
- [ ] 扩展第二资源后无需修改安卓特定设备按钮；明确模拟/实物证据。

## 4. 真机步骤

1. 构建并安装 debug APK；开启模拟模式先检查界面与操作。
2. PC 模拟 HTTP 服务显式绑定测试网卡，手机与 PC 同网段；必要的防火墙设置由实际环境决定，记录服务地址。
3. 切真实模式，输入 PC 地址，检查获取能力与外设控制响应。
4. 烧录 ESP 固件，记录串口 IP/端口；手机系统设置手动连接对应热点。
5. App 连接 ESP，读取初始状态，开启/关闭外设，核对逻辑回报和实物变化。
6. 进行离网、重启、恢复测试；保留网络条件和错误日志。
